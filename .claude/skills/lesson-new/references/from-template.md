# 「활동지 양식.docx」로 새 차시 만들기 (1판 2026-09-30 · 2판 2026-10-17)

선생님이 `docs/templates/활동지 양식.docx` 에 내용을 적어 와서 **"이 양식으로 N차시 만들어줘"** 라고 할 때 따른다.
PDF 로 만들 때(`from-pdf.md`)와 흐름·부품·확인은 같고, **읽는 법과 칸·표기 해석**만 다르다.
2판은 칸이 활동지 순서(`docs/rules/order.md` §1)와 같다 — 기본 정보 → 도입 → 활동 n → 정리.

## 1. 읽기

이 PC 는 Read 도구·pandoc 으로 docx 를 못 연다 → 설치 없이 도는 읽기 도구:

```
node .claude/skills/lesson-new/references/docx-read.mjs "<채운 양식.docx>" > <scratchpad>/양식.md
```
- 제목 1~3 → `#`, 목록 → `-`/`1.`, 표 → `| 칸 |`(칸 안 여러 줄은 `<br>`), 문서 안 그림 → `[문서 안 그림]`.
- Word · Google 문서(파일 → 다운로드 → .docx) 둘 다 된다. 문서 안 그림이 있으면 파일로 따로 달라고 한다.
- **`# ✍️ 여기부터 작성` 부터 `# 📎 참고` 앞까지만** 내용이다. 그 위(사용법·한눈에)와 📎 참고(표기법·작성 예시)는 무시.
  📎 제목이 지워졌으면 끝까지 읽되, 「참고 2. 작성 예시」의 07 로블록스 글이 섞여 들어오지 않았는지 본다.
- `※` 로 시작하는 줄은 양식의 안내 문구, 칸 이름 뒤 `(꼭)`·`(선택)` 은 표시 — 무시.
- 양식에 학생 이름 같은 개인정보가 있으면 쓰지 않는다.

## 2. 칸 → 활동지 카드 (2판)

| 양식 칸 | 활동지(`order.md` §1, 틀 `_templates/order`) | 비었을 때 |
|---|---|---|
| 학습 주제 **(꼭)** | TODAY_TOPIC 큰 제목 · `lesson.json` title · `--title` | 없으면 만들기 전에 묻는다 |
| 차시 | `LESSON_NN` 태그 · `· N차시` · 폴더 번호 | 그 단원의 다음 빈 번호로 정하고 알린다 |
| 단원 | TODAY_TOPIC 단원 이름 줄 · 폴더 `<단원>` | 주제를 보고 골라 확인받는다 |
| 학습 목표 | TODAY_GOALS 목표 상자(`num-coin`) | 초안 |
| 도입 — 동기유발 (제목 · 내용) | `도입` WARM_UP — 제목 → `.m-title`, 내용 → 본문·부품 | 초안 |
| 도입 — 학습주제 제시 (제목 · 내용) | `도입` TODAY_TOPIC(학습주제 제시) | 초안 |
| 활동 n **(꼭, 1개 이상)** (제목 · 내용) | `전개` ACTIVITY_n — 제목 → 질문 스티커 `.m-title--q`, 내용의 `1. 2. 3.` → 단계 소제목 `.m-hd2` + 그 아래 부품 | 0개면 묻는다. 제목만 비면 초안 |
| 정리 — 핵심 정리 (제목 · 내용) | `정리` KEY_SUMMARY(order.md 이름은 "핵심 요약") | 초안 |
| 정리 — 형성평가 (문제) | `정리` CHECK_UP — 실제로 눌러서 채점되는 O/X 등(`num-coin--lilac`) | 초안 |

- **빈 칸 규칙(선생님 결정 2026-10-17)**: 학습 주제·활동 말고는 모두 선택이다.
  - **비어 있음** → Claude 가 활동 내용을 보고 초안을 써서 spec.md 에 "(Claude 초안)" 표시로 적고, ✋ 확인받은 뒤 넣는다.
  - **`없음`** → 그 카드를 활동지에서 뺀다(순서에서 그 줄만 빠짐). 진행률 칸 목록에서도 뺀다.
  - **`물어봐 줘`**(또는 `(물어봐 줘)`) → AskUserQuestion 으로 묻는다(한 번에 4개까지).
- 활동 수 = 적힌 활동 덩어리 수. 제목·내용이 모두 빈 덩어리(지우지 않고 남긴 「활동 3」 등)는 없는 것으로 본다.
  활동 5개 이상이면 색은 act1~4 를 돌려 쓴다(`order.md` §3).
- 표기법 없이 말로 적은 활동은 뜻대로 가장 가까운 부품을 고르고, 고른 것을 spec.md 와 보고에 적는다.

## 3. 표기 → 부품 (`from-pdf.md` §2 표의 부품을 쓴다)

| 양식 표기 | 부품 |
|---|---|
| `1. 2. 3.` (활동 내용의 단계) | 단계 소제목 `.m-hd2`("1. …"), 단계 글 안 이름표는 그 아래 부품으로 |
| `[[정답]]` (문장 속) | 문장 속 글자 칸 `.st-mean` + `textarea.blank.blank--inline`(03). 정답은 `answers.json` fill |
| `[[ ]]` | 같은 칸, 정답 없음(정답지 비움) |
| `[쓰기 칸 N줄]` · `예시:` | `textarea.blank rows=N`. 예시 답은 placeholder 로, 정답지에서는 비움("정답지에 채울 칸"이 "예시 답도"면 채움) |
| `[안내]` · `[Tip]` · `[주의]` | `.callout--info` · `.callout--reason` · `.callout--info`(⚠️ 라벨) — 콜아웃은 냉색만 |
| `[제미나이]` | `.callout--gemini` + 질문 예시 + 정리 칸 |
| 워드 표(`[표]`) | `.type-scroll > table.type-table`(핵심 정리 표는 틀의 `table.ord-sum`), 칸 안 `[[…]]` 은 `textarea.blank` |
| `[하나 고르기]` | 문항 1개 `VQ`(02) · 여러 개 `DQ`/`FQ`(03·06·07 분석 유형 = `glass-chip`). `(정답)` 보기, `이유:` 는 오답 피드백(없으면 새로 씀) |
| `[모두 고르기]` | `MQ` + 정답 확인(01) |
| `[O/X]` (`→ O` / `-> X`) | 틀(ai/01)의 O/X — **누르면 바로 채점, 맞아도 틀려도 이유**(`(이유: …)` 를 둘 다에 씀, 없으면 새로 씀). 형성평가 CHECK_UP 모양(`order.md` §2-0-5, `parts.md` §3) |
| `[이름표 끌어 놓기]` (`칸 → 정답`) | 공용 `chip-slot`, 여러 개면 `data-ca-group` + 버튼 채점(02) |
| `[순서 배열]` | `seq-order` — 새 차시는 ai/01 표식: `.seq-activity#id` + `data-fb-all/-partial/-none/-incomplete`, 칸 `data-answer` 차례가 정답, 버튼 `[data-seq-check]`·`[data-seq-reset]`(04 는 고정 id 그대로) |
| `[그림]` | 새 SVG(`from-pdf.md` §6) — 글자는 CookieRun Bold(`references/svg-font.mjs`), 비교는 두 칸·화살표 이름은 옆(`parts.md` §4). 받은 파일·영상(mp4)이면 「그림을 누르면 영상」 `.ai-vid` |
| `[붙여넣기 칸]` | `paste-zone`(06·07) |
| `[링크]` | 새 탭 버튼(`.gm-btn` 모양) |
| `[메모]` | 만드는 방법 부탁 — 활동지에 넣지 않는다 |

버튼은 모두 유리 알약(`glass-pill` · `glass-chip`) — `lesson-new` SKILL §3.

부품 모양(가운데 정렬 · 이름표 2열 · 개념 표/카드 · 핵심 정리 이름표 등)은 **`docs/rules/parts.md`** 를 따른다.

## 4. 만들 때 부탁 (모두 선택)

비었으면 아래 기본값을 쓰고 **알린다**.

| 칸 | 기본값 |
|---|---|
| 틀 | 4탭(`_templates/order` 그대로) — "한 화면"이면 standalone 으로 만들지 묻는다 |
| 공개 | 바로 공개(`status: live`, push 해야 배포) |
| 함께 주는 파일 | 없음 — 데이터·원자료·그림은 `input/<단원>/` 에 두고 커밋하지 않는다 |
| 데이터 나눠 주는 법 | 묻는다(수업자료 폴더 / 활동지 내려받기 버튼) |
| 맨 앞 안내 상자 | 빼기(지금 틀에 없음). "넣기"면 목표 다음·도입 앞에(`order.md` §1) |
| 교사용 정답지에 채울 칸 | 정답 있는 칸만 |
| 채점 방식 | 활동마다 알맞게(고르기 칩은 누르면 바로, O/X 묶음은 ✅ 정답 확인) |

## 5. 1판(미션 1~5)으로 채워 온 양식

1판은 `# ✍️ 여기부터 작성` 아래 끝까지가 내용이다. 칸을 이렇게 옮겨 읽는다.
- `오늘의 목표` → 학습 목표 · `미션 n`(미션 제목 · 도입 문장 · 활동) → 활동 n(제목 · 내용 첫 문단 · 단계) · `미션 5 — 형성평가` → 형성평가.
- 기본 정보의 `제목` → 학습 주제. `한 줄 소개` 는 틀에 자리가 없으니 학습주제 제시 내용에 쓸지 묻는다.
- 1판에 없는 칸(동기유발 · 학습주제 제시 · 핵심 정리)은 "비어 있음"으로 보고 초안 → 확인.

## 6. 그다음

`from-pdf.md` §4(폴더 · spec.md) → §5(조립) → §7(확인)과 똑같이. 새 차시는 `lesson-new` SKILL §3 대로 틀 `_templates/order` 에서 출발한다.
spec.md 의 원자료에는 양식 파일 이름을, 흐름 표는 `order.md` 순서(도입 2 · 전개 n · 정리 2, "없음"으로 뺀 카드는 빼고)로 적는다.
채운 양식 파일은 `input/<단원>/` 에 두고 커밋하지 않는다.

## 양식 고치기

양식 원본은 `references/template-docx.mjs`(docx 패키지는 scratchpad 에만 설치) → `docs/templates/활동지 양식.docx`.
칸을 바꾸면 이 파일 §2 와 양식의 「한눈에」 표를, 표기를 새로 만들면 이 파일 §3 표와 양식의 「📎 참고 1. 활동 표기법」 표를 같이 고친다.
확인:
1. `docx-read.mjs` 로 다시 읽어 구조(✍️ ~ 📎 사이 칸)가 그대로인지.
2. `references/docx-render.ps1` 로 쪽 그림을 떠서 눈으로 — **1쪽(사용법·한눈에)이 한 쪽에 들어가 「✍️ 여기부터 작성」이 2쪽에서 시작**하는지, 제목·「제목:」이 쪽 끝에 홀로 남지 않는지.
