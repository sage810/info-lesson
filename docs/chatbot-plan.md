# 활동지 챗봇 (Upstage) — 고민 정리

> **상태: 고민 단계. 아직 만들지 않는다.** (선생님과 이야기한 내용 정리, 2026-10-30)
> 결정이 나고 만들기 시작하면 이 문서를 `docs/rules/chatbot.md` 로 옮겨 규칙 문서로 다듬는다.

차시 활동지마다 학생의 질문에 답해 주는 챗봇을 넣을 수 있는지, 넣는다면 어떻게 할지 정리한 글.

## 1. 전제

- 저장소와 사이트(GitHub Pages)는 **공개**다. → Upstage API 키를 화면(`lesson.html`·`dist/`)에 절대 넣지 않는다. 반드시 **중계 서버**를 거친다.
  (지금 NEIS 키를 `apps-script/Code.gs` 의 스크립트 속성에만 두고 중계하는 것과 같은 원칙.)
- 사용자는 중학생. 만 14세 미만이 섞여 있어 생성형 AI 사용은 **학교·교육청 지침과 보호자 동의 확인**이 먼저다. → 선생님 확인 사항.
- 수행평가(시험지) 차시에는 **넣지 않는다**. `answers.json` 은 챗봇에도 주지 않는다.

## 2. 구조

```
학생 화면(GitHub Pages) ──→ 중계 서버(키 숨김·횟수 제한·기록) ──→ Upstage 대화 API
                                                        └ UPSTAGE_KEY 는 서버 비밀값에만
```

- 차시마다 켜고 끄기: `lesson.json` 에 `"chatbot": true` (테마 `"theme"` 처럼 빌드가 넣거나 뺀다). 수행평가 차시는 값이 있어도 무시.
- 차시마다 아는 내용: 빌드 때 `spec.md` 와 활동지 본문을 짧게(1~2천 자) 요약해 "배경 지식"으로 넣고, 그 범위 안에서만 답하게 한다.
- 답하는 방식: **개념 설명 + 힌트, 빈칸 정답은 주지 않음**(추천). 수업 범위 밖 질문은 부드럽게 거절.

## 3. 중계 서버 — Apps Script 대신 Cloudflare Workers (추천)

Apps Script 의 두 문제: ① 동시 처리 한도가 낮아 한 반 30명이 한꺼번에 물으면 느려지거나 실패 ② 답을 한 글자씩 흘려보내지(스트리밍) 못해 다 끝난 뒤 한 번에 뜸(몇 초 멈춤).

| 후보 | 동시 접속 | 스트리밍 | 무료 범위 | 손 가는 정도 |
|---|---|---|---|---|
| **Cloudflare Workers** (추천) | 사실상 제한 없음, 처음 켜질 때 지연 없음 | 됨 | 하루 10만 요청 | 계정 하나 + 명령 한 번. 이 저장소의 GitHub Actions 에서 함께 배포 가능 |
| Vercel / Netlify Edge Functions | 좋음 | 됨 | 넉넉함(개인·비상업 조건) | 비슷하나 계정·프로젝트 하나 더 |
| Deno Deploy | 좋음 | 됨 | 넉넉함 | 비슷함 |
| Firebase / Cloud Run | 좋음 | 됨 | 결제 등록 필요, 처음 켜질 때 몇 초 느림 | 과함 |
| Apps Script (지금) | 30명 동시면 아슬아슬 | **안 됨** | 넉넉함 | 이미 있음 |

Cloudflare 를 고른 이유 하나 더: 앞에 **AI Gateway**(무료)를 끼우면 코드 없이 요청 기록·횟수 제한·비용 집계가 되고, Upstage 같은 외부 모델도 그대로 통과시킨다. "오늘 학생들이 뭘 물었나"를 보기 좋다.

- 계정은 이메일만 있으면 무료. 배포용 토큰은 GitHub 저장소 비밀값(secrets)에 → 공개 저장소여도 안전.
- 어떤 서버를 쓰든 **진짜 병목은 Upstage 쪽 분당 처리 한도**다. 요금제별 한도를 시작할 때 최신 문서로 확인한다.

## 4. "영리하게": 질문을 층으로 나눈다

동시 30명이 같은 순간 "클래스가 뭐예요?"를 물어도, 모든 질문을 모델에 보낼 필요가 없다.

```
① 공짜·즉시 층   자주 묻는 질문 칩(차시별 5~8개) → 미리 써 둔 답, API 호출 0
② 캐시 층        같은(정규화한) 질문이 또 오면 저장된 답 그대로 → 즉시, 비용 0
③ 스트리밍 층    새 질문만 Upstage 로, 글자가 나오는 대로 흘려보냄 → 1초 안에 첫 글자
④ 과부하 층      Upstage 가 "너무 많아요(429)" 하면 서버가 "잠깐만요" 신호 →
                 화면은 "친구들 질문이 많아요, 몇 초 뒤 다시 물어볼게요" 하고 알아서 재시도
```

- ① 만으로 수업 중 질문의 절반 이상이 걸러질 것으로 본다. 차시별 FAQ 는 `spec.md` 에서 Claude 가 초안을 뽑고 선생님이 다듬는다. 활동지 안 "힌트 카드"로 보여도 자연스럽다.
- ③ 체감 속도 줄이는 요령: 배경 지식 짧게(1~2천 자) · 대화 기억은 최근 4턴만 · 답 길이 300자 안팎. 중학생 상대 설명은 짧을수록 빠르고 싸다.
- ④ 가 핵심. 실패를 "오류"가 아니라 "줄 서기"로 보이게 하면 수업이 끊기지 않는다.

## 5. 공개 주소를 아무나 못 쓰게 하는 장치 (서버를 바꿔도 똑같이 필요)

1. **수업 코드** — 선생님이 칠판에 오늘 코드를 띄우고 학생은 처음 한 번 입력. 코드가 없거나 지났으면 서버가 응답하지 않음. 외부인 차단에 가장 단순하고 효과적.
2. **횟수 제한** — 학생 한 명(브라우저에 저장한 익명 번호) 분당 N번 + 전체 분당 상한. Cloudflare 내장 기능.
3. **끄는 스위치** — 선생님용 작은 관리 화면(비밀번호)에서 차시별 켜기/끄기. 수행평가 차시는 빌드에서 아예 뺌.
4. **출처 확인** — 요청이 `sage810.github.io` 에서 왔는지 확인(약하지만 가벼운 남용은 막음).
5. **질문 길이 제한** · **비용 상한** — Upstage 계정에 월 사용 한도.

## 6. 걱정 → 대응 표

| 걱정 | 내용 | 대응 |
|---|---|---|
| 남이 마구 씀 | 주소가 공개라 누구나 불러 요금을 쓰게 할 수 있음 | §5 수업 코드 · 횟수 제한 · 끄는 스위치 · 비용 상한 |
| 동시 접속 | 한 반 25~30명이 한꺼번에 물음 | Cloudflare Workers + §4 층 나누기 + ④ 줄 서기 |
| 답이 늦게 뜸 | 몇 초 멈춤 | 스트리밍 + 짧은 배경 지식·짧은 답 + FAQ 칩 |
| 학생 나이 | 만 14세 미만 생성형 AI 사용 | 학교·교육청 지침·보호자 동의 — **선생님 확인** |
| 개인정보 | 학생이 이름·전화번호를 적을 수 있음 | 이름 받지 않음 · 안내 문구 · 개인정보처럼 보이는 글은 보내기 전에 막기 |
| 답 노출 | 빈칸 정답을 알려 주면 활동 의미가 사라짐 | 힌트만 모드 · 수행평가 차시 제외 · `answers.json` 미제공 |
| 엉뚱한 질문·틀린 답 | 수업과 무관한 질문, 잘못된 답 | 범위 밖 거절 · 질문 기록을 선생님이 봄 |

## 7. 화면 쪽

- **위치**: 오른쪽 아래 둥근 유리 알약 버튼(💬) → 누르면 대화 창. 메모 모드의 📝 버튼(`shared/runtime/msi-memo.js`)과 자리가 겹치므로 둘의 위치를 정해야 한다.
- **모양**: 버튼은 오로라 유리 알약 규칙(`DESIGN.md`), 색은 역할 토큰, 차시 테마를 따른다.
- **PDF·인쇄**: 챗봇 창·버튼은 PDF 에 나오지 않게(`no-pdf`).
- **교사용 화면**: 챗봇을 빼거나 질문 기록 보기로 대신.
- **ai 단원과 잘 맞음**: 「이 챗봇은 어떻게 대답할까?」 자체를 활동으로 쓸 수 있다(인공지능 모델·학습 데이터·틀린 답이 나오는 이유).

## 8. 시작할 때 확인할 것

- Upstage 모델 이름·요금·**분당 처리 한도**(요금제별) — 최신 문서로.
- Upstage 가 OpenAI 호환 형식(`/v1/chat/completions`, `stream: true`)인지 — 맞으면 스트리밍 통과가 간단하다.
- Cloudflare Workers 무료 한도·AI Gateway 가 Upstage 를 통과시키는 방법.
- 학교 지침(§1).

## 10. 추천 순서

1. 학교 지침 확인(§9-7).
2. Cloudflare 계정 → Worker 중계 + AI Gateway, ai/02 에서 시범.
