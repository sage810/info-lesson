# 활동지와 수업 모형 — 어떤 모형으로 설명할 수 있나

> **상태: 고민 정리.** (선생님과 이야기한 내용, 2026-10-30)
> 계기: 어떤 교사가 "AI 자동화 플랫폼의 기반이 되는 STAD 수업 모형"을 현장에 적용한 파일럿 연구를 했다는 이야기를 듣고,
> 우리 활동지(`lessons/<단원>/<차시>/lesson.html`)는 어떤 수업 모형과 같이 이야기할 수 있는지 정리.
> 인용·서지는 아직 원문 확인 전이다(§7).

## 1. 우리 활동지의 실제 모습 (모형을 고르는 근거)

- 뼈대: **도입(동기유발 · 학습주제 제시) → 전개(활동 1, 2, …) → 정리(핵심 요약 → 형성평가) → PDF 제출** (`docs/rules/order.md`).
- 학생 **한 명이 자기 속도로** 끝까지 간다(개별 디지털 활동지). 진행률 위젯이 따라다닌다.
- 실습 차시(예: ai/02)는 **단계 캡처를 보며 따라 하기**(활동 1) → **내 것 만들어 기록하기**(활동 2).
- 형성평가는 **누르면 바로 채점 + 맞아도 틀려도 이유**.
- 교사용: 진행률 없는 화면 · 정답지 PDF · 수업용 슬라이드(`present.html`).
- 4탭(이용 규칙 · 시간표 · 급식 · 활동지)은 수업 운영 루틴.

## 2. STAD 와 견주면 — 결이 다르다

STAD(Slavin) 는 협동학습 모형: ① 교사 설명 → ② **이질 모둠 학습** → ③ **개별 퀴즈** → ④ **개인 향상 점수** → ⑤ **모둠 보상**.
"모둠이 함께 공부하되 책임은 개인에게, 보상은 모둠에게."

| STAD 요소 | 우리 활동지 |
|---|---|
| ① 교사 설명 | 있음 — 수업용 슬라이드 |
| ② 모둠 학습 | **없음** — 개별 |
| ③ 개별 퀴즈 | 있음 — 형성평가 즉시 채점 |
| ④ 개인 향상 점수 | **없음** |
| ⑤ 모둠 보상 | **없음** |

→ "같은 모형"이라 하기보다 **"다른 모형 위에서 같은 플랫폼(디지털 활동지 · 자동 채점)을 쓴 사례"**로 놓는 것이 정직하다.
STAD 와 연결하고 싶으면 **모둠 향상 점수 · 모둠 인정**을 얹는 변형(예: 형성평가 점수를 모둠별로 모아 보는 교사용 시트)이 가능하지만, 그건 지금 설계와 다른 수업이라 따로 설계해야 한다.

## 3. 잘 맞는 모형 — 추천 순서

### 1순위 · DMM(시연 중심) 모형 — 정보 교과 안에서 바로 통하는 이름

교육부·KERIS(2015) SW교육 교수·학습 모형 다섯 가지(DMM · UMC · DDD · NDIS · DPAA(P)) 중
**DMM = 시연(Demonstration) → 모방(Modeling) → 제작(Making)**. ai/02 가 이 순서 그대로다.

| DMM | ai/02 에서 |
|---|---|
| 시연 | 활동 1 의 35단계 캡처(교사 시범을 화면 캡처로 옮긴 것) · 수업용 슬라이드 |
| 모방 | 캡처를 보며 엔트리에서 똑같이 따라 하기 |
| 제작 | **내가 고른 두 이미지**로 내 모델 만들기 → 활동 2 에 기록 |

- 정보 교사 독자·심사자에게 가장 짧게 통하는 이름표.
- 만들기가 없는 **개념 차시**(ai/01 「인공지능이란?」 등)는 DMM 보다 2순위(직접 교수)로 설명하는 것이 맞다.
- 뒤 차시에서 주어진 코드를 고쳐 쓰는 활동이 생기면 **UMC(Use → Modify → Create)** 도 쓸 수 있다.

### 2순위 · 직접 교수 · 점진적 책임 이양(GRR) — 일반 교수학습 이론으로 받칠 때

- **점진적 책임 이양**(Pearson & Gallagher, "I do → We do → You do"):
  활동 1 앞부분(시범 그대로) → 활동 1 뒷부분(단계 글만 보고) → 활동 2(내 모델, 혼자) → 형성평가. 책임이 교사·활동지에서 학생으로 넘어가는 구조.
- **Rosenshine 수업 원리**(2012): 작은 단계 제시 · 예시 보여 주기 · 안내된 연습 · 이해 확인 · 높은 성공률 · 스캐폴드 · 독립 연습.
  35단계 캡처 = "작은 단계 + 예시", O/X 즉시 채점 = "이해 확인".
- 도입 → 전개 → 정리(핵심 요약 · 형성평가) 뼈대는 **Gagné 9가지 수업 사태**와 겹친다(주의 집중 → 목표 제시 → … → 수행 유도 → 피드백 → 평가).

### 3순위(둘째 렌즈) · 인지적 도제 또는 Kolb 경험학습 — 활동 2 · 정리를 설명할 때

DMM·직접교수는 활동 1 은 잘 설명하지만 **활동 2 와 정리**는 부족하다. 둘 중 하나를 겹쳐 쓴다.

**인지적 도제**(Collins, Brown & Newman) 6요소 — ai/02 에 거의 1:1.

| 요소 | ai/02 |
|---|---|
| 모델링 | 캡처 시범 |
| 코칭 | 교사 순회 + (예정) 챗봇 힌트(`docs/chatbot-plan.md`) |
| 스캐폴딩 → 페이딩 | 단계 캡처 → 단계 글만 → 내 모델 |
| 명료화(articulation) | 활동 2 문장 빈칸 「내가 만든 모델: ○○와 ○○를 구분하는…」 |
| 반성(reflection) | 「틀리게 분류했어요, 어떻게 해야 할까요?」 · 형성평가 「맞아도 틀려도 이유」 |
| 탐색(exploration) | 구분할 대상을 학생이 고름 |

**Kolb 경험학습 순환** — 구체적 경험(모델 만들기) → 반성적 관찰(결과 기록·붙여넣기) → 추상적 개념화(핵심 요약 표: 클래스·학습 데이터·테스트 데이터) → 능동적 실험(데이터 더 넣어 다시 학습).
"해 보고 → 개념 이름 붙이기" 순서인 ai 단원 차시에 잘 맞는다.

### 참고 · 5E 모형

Engage(동기유발 그림) → Explore(활동 1) → Explain(핵심 요약) → Elaborate(활동 2 Q3) → Evaluate(형성평가).
과학 쪽 독자에게 익숙하지만, 우리 순서는 활동 2 가 핵심 요약보다 앞이라 조금 어긋난다.

## 4. 모형 이름 바깥 — 이 활동지만의 특징 (연구라면 이쪽이 더 새 이야기)

- **스캐폴딩의 일부를 교사가 아니라 활동지가 맡는다**: 단계 캡처 · 즉시 채점 · 이유 피드백 · 진행률. 교사는 순회·개별 도움에 시간을 쓴다. 챗봇이 붙으면 "코칭"까지 활동지가 분담.
- **형성평가가 수업 안에 박혀 있고 즉시 피드백**: Bloom 완전학습의 "형성평가 → 교정"을 매 차시 작은 단위로.
- **4탭 포털**: 수업 모형은 아니지만 "수업 루틴"으로 기술할 만하다.
- **결과물 제출이 PDF 한 장**: 평가·기록 부담을 줄이는 운영 설계.
