# 스티커 테마 색 안내 — 쓰인 색과 새 색 뽑는 법

스티커 테마(`design-sticker/`, 차시 `"theme": "sticker"`, 지금 ai/01~04)에 색을 고르거나 더할 때 보는 문서입니다. 다른 에이전트가 이 문서만 읽고 같은 톤의 색을 뽑을 수 있게 썼습니다.

- **값의 원본은 [tokens.json](tokens.json)** 입니다. 아래 표는 2026-11-07 기준 사본이라, 어긋나면 `tokens.json` 이 맞습니다.
- 역할 하나하나의 색은 자동 생성 표 [color-map.md](color-map.md) 에 있습니다. 이 문서는 색을 **층별로 묶고, 왜 그 값인지와 새 색을 뽑는 법**을 적습니다.
- 표의 L·C·H·대비는 눈대중이 아니라 모두 계산한 값입니다.

| 기호 | 뜻 |
|---|---|
| **L** | 밝기, 0(검정)~1(흰색) |
| **C** | 채도, 0이면 회색 |
| **H** | 색상각, 0~360° (3 분홍 · 55 피치 · 98 노랑 · 168 민트 · 247 하늘 · 297 라벤더) |
| **ΔE** | 두 색의 거리. 머리 색끼리 가장 가까운 쌍(페리윙클–라벤더)이 .020 |
| **잉크** | 갈색 잉크 글자 `#4A3B32` 와의 대비 |

L·C·H 는 OKLCH 값입니다. **고를 때만 쓰고, 파일에는 `#hex`·`rgba()` 만 적습니다.** `oklch()`·`color-mix()` 는 활동지 PDF 저장이 못 읽어서 빌드가 멈춥니다.

## 1. 분위기

> 크림색 스케치북 종이에 갈색 잉크로 선을 긋고, 우유를 탄 듯 뽀얀 파스텔 스티커를 붙인 포근한 활동지.

이 톤은 낱낱의 색보다 아래 규칙에서 나옵니다. 새 색도 이 규칙 안에 있어야 합니다.

| # | 규칙 | 실측 |
|---|---|---|
| 1 | **순백·순흑이 없다.** 종이도 잉크도 따뜻하다 | 가장 밝은 색 `#FFFDF8`(L .994) · 가장 진한 색 `#4A3B32`(L .366) · 잉크 H 53 · 종이 H 86~89 |
| 2 | **넓을수록 옅다.** 면적이 작아져야 채도를 올린다 | 몸통 C .009~.024 → 머리 C .030~.076 → 강조 C .049~.100 → 글자 C .085~.137 → 3px 포커스 고리 C .157 |
| 3 | **경계는 색이 아니라 잉크 선이 만든다** | 머리 색과 크림 종이의 대비는 1.14~1.49:1 뿐. 3px 잉크 테두리 덕분에 옅어도 또렷하다 → 눈에 띄게 하려고 색을 진하게 만들 필요가 없다 |
| 4 | **글자는 어디서나 잉크** | 머리 위 잉크 글자 7.05~9.23:1. 흰 글자는 「진행 중」 배지(크림 글자 5.11:1)와 기본 테마에서 내려온 단계 번호(6-2)뿐 |
| 5 | **그림자도 잉크색** | `rgba(74,59,50,.12~.2)` 로 아래로 번진다. 검은 그림자는 없고, 어긋난 그림자는 `.msi-pill` 고른 상태 한 곳만 남아 있다. PDF 버튼만 제 색으로 번진다 |
| 6 | **위→아래로 따뜻함·차가움을 번갈아** | 카드 순서 표(2-3) 참고. 같은 쪽이 연달아 오는 곳은 마지막 두 장뿐 |
| 7 | **색마다 밝기·채도가 다르다** | 버터 L .948·C .076, 베이비블루 L .917·C .030, 밀키핑크 L .870·C .062. 같은 L·C 로 색상각만 돌리면 이 느낌이 안 나온다 |

**앱 예외**: 교육과정 분석 웹앱(Achievement-based evaluation procedure)은 6번 대신 읽는 순서대로 색상환을 따라 칠하고(살구→버터→연두→민트→아쿠아→페리윙클→라벤더), 입력칸은 분홍 종이 대신 크림 종이를 쓴다(선생님 결정 2026-11-07).

**이 톤을 깨는 것**: 어두운 바탕 · 형광·네온(선생님 취향, `docs/templates/claude-design-prompt.md`) · 회색기 도는 파스텔 · 탁한 베이지 · 파스텔 위 흰 글자 · 순수 검정 글자 · 유리·오로라 빛.

## 3. 새 색 뽑는 순서

### 3-1. 정말 새 색이 필요한가

앞에서 해결되면 거기서 멈춥니다.

1. **있는 역할을 돌려 쓴다.** 활동이 5개 이상이면 `act1`~`act4` 를 차례로 씁니다.
2. **예비색 `moss` 를 쓴다**(2-11).
3. **새 색상각을 뽑는다.** 진짜 빈자리는 **H 76 근처와 H 145 근처, 두 곳뿐**입니다(5장).

**색상각이 비어 보여도 새 색이 아닐 수 있습니다.** 채도가 낮아서 20° 떨어져도 거의 같아 보입니다(H 187 은 아쿠아와 20° 떨어져 있지만 ΔE .015). 구별이 꼭 필요한데 색이 모자라면, 색을 더 늘리지 말고 글·기호·아이콘으로 구별합니다.

### 3-2. 층 고르기

색을 고르기 전에 **어느 자리에 쓸지**부터 정합니다. 자리가 L·C 를 정합니다.

| 층 | 쓰는 곳 | 실측 L | 실측 C | 글자 | 머리에서 만드는 법 |
|---|---|---|---|---|---|
| **몸통** `body` | 카드 몸통, 넓은 바탕 | .969~.986 | .009~.024 | 잉크 | 흰색 75% 섞기 |
| **칩** `chip` | 이름표, 상태 바탕, 안내 | .901~.960 | .023~.068 | 잉크 | 흰색 35% 섞기(실측 25~45%) |
| **머리** `head` | 카드 머리, 과목 | 3-4 표 | 3-4 표 | 잉크 | 기준 |
| **강조** `strong` | 번호 동전, 대표 버튼, 작은 면 | .812~.890 | .049~.100 | 잉크 | L −.055, C ×1.45, 상한 .10(실측 L −.03~−.06, C ×1.2~1.6) |
| **진한 글자** `deep` | 글자, 가는 선 | .478~.552 | .085~.137 | — | L .55 에서 내려가며 4.5:1 찾기, C 상한 .10 |

### 3-3. 색상각 고르기

뜻이 이미 정해진 자리가 있습니다. 같은 뜻이 아니면 피합니다.

| 색상각 | 색 | 뜻 |
|---|---|---|
| H 355~8 | 분홍 | 대표 강조(제목줄·탭·PDF·진행률·포커스·목표 동전) |
| H 10~30 | 살몬·로즈 | 틀림·오류 |
| H 155~175 | 민트 | 맞음·저장 끝·정답 확인 |
| H 94~98 | 버터 | 처리 중·단원 이름(뜻이 약함, 카드 머리로도 씀) |
| H 247~254 | 베이비블루 | 주요 버튼·바깥 사이트 버튼(뜻이 약함, 카드 머리로도 씀) |

민트(`warmup`)처럼 장식 카드가 같은 자리를 쓰는 경우도 있으니, 상태 표시 옆에는 두지 않습니다.

**받은 색이 있을 때**(학교 상징색, 사진, 벽지): **색상각 H 만 가져오고 L·C 는 3-4 표를 따릅니다.** 지금 팔레트도 그렇게 만들어졌습니다.

고른 H 의 앞뒤 기준점 사이를 비례로 나눕니다. 기준점 사이에서 계산한 값이 sRGB 밖이면 C 만 줄입니다.

| 98 | 버터 | .948 | .076 | `#FBEFB4` |
| 121 | 연두 | .907 | .070 | `#D9E8B4` |

**왜 공식이 아니라 표인가**: 이 11색은 그 색상각에서 낼 수 있는 최대 채도 대비 27~85% 로 제각각이라, 「최대 채도의 몇 %」 같은 공식이 맞지 않습니다.

**이 표를 믿어도 되는 근거**

- 한 색을 빼고 나머지로 그 색을 맞혀 보면 오차가 평균 L .017 · C .008, 최대 L .038 · C .015 입니다. 도구의 허용 범위(L ±.04)는 이 최대 오차에서 정했습니다. C 는 위로 +.02, 아래로 −.035(`olive` 같은 더 뽀얀 색을 받으려고) 입니다.
- 기준점에 넣지 않은 팔레트 색도 표 위에 놓입니다. 차시 알약 `#FFE3BD`(실제 L .929·C .058 / 표 L .930·C .059), 생활 중국어 `#F4CBDE`(L .883·C .052 / L .881·C .053), 자율활동 `#E1D4F0`(L .889·C .040 / L .889·C .036).

### 3-6. 눈으로 보기

숫자를 통과해도 끝이 아닙니다. **3px 잉크 테두리 + 크림 바탕** 위에 **이웃 색과 나란히** 놓고 캡처해 봅니다(`tokens.css`·`components.css` 를 불러와 `.msi-card` 로).

- 스티커처럼 보이는가, 형광펜이나 먼지처럼 보이는가?

### 3-7. 선생님께 여쭙고 넣기

1. 후보 2~3개와 추천안을 캡처로 보여 드리고 답을 받습니다(`CLAUDE.md`: 결정할 일은 먼저 묻기).
2. `tokens.json` 의 `role` 에 넣습니다. `$value` 는 `#hex`, `$description` 은 색 표의 이름 칸, `$note` 는 이유입니다.
   ```json
   "act5-head": { "$value": "#FFE4BE", "$description": "ACTIVITY_5 머리(꿀)", "$note": "H 76, 도구 make 결과" },

4. 기본 `design/tokens.json` 에 없는 역할은 스티커 차시에서만 있습니다. 기본 테마 차시에 쓰면 변수가 비어 색이 안 나옵니다.

  return [4.0767416621 * l - 3.3077115913 * m + 0.2309699292 * s, -1.2684380046 * l + 2.6097574011 * m - 0.3413193965 * s, -0.0041960863 * l - 0.7034186147 * m + 1.707614701 * s];
}
const maxC = (L, H) => { let C = 0.4; while (C > 0 && linRgb(L, C, H).some((x) => x < -1e-4 || x > 1 + 1e-4)) C -= 0.001; return Math.max(C, 0); };
function hex(L, C, H) { // sRGB 밖이면 채도만 줄인다(색상각·밝기는 지킴)
  C = Math.min(C, maxC(L, H));
  return '#' + linRgb(L, C, H).map((x) => Math.round(gam(Math.min(1, Math.max(0, x))) * 255).toString(16).padStart(2, '0')).join('').toUpperCase();
}
const mixWhite = (h, t) => '#' + rgb(h).map((c) => Math.round(c + (255 - c) * t).toString(16).padStart(2, '0')).join('').toUpperCase();
const lum = (h) => { const [r, g, b] = rgb(h).map(lin); return 0.2126 * r + 0.7152 * g + 0.0722 * b; };
const cr = (a, b) => { const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
const de = (a, b) => { const [x, y] = [lab(a), lab(b)]; return Math.hypot(x[0] - y[0], x[1] - y[1], x[2] - y[2]); };
const ANCH = Object.values(HEADS).map(lch).sort((a, b) => a.H - b.H);
function anchor(H) { // 카드 머리 11색 사이를 색상각으로 보간
  H = ((H % 360) + 360) % 360;
  const n = ANCH.length;
  for (let i = 0; i < n; i++) {
    const a = ANCH[i], b = ANCH[(i + 1) % n], bh = i === n - 1 ? b.H + 360 : b.H, x = i === n - 1 && H < a.H ? H + 360 : H;
    if (x >= a.H && x <= bh) { const t = (x - a.H) / (bh - a.H); return { L: a.L + (b.L - a.L) * t, C: a.C + (b.C - a.C) * t }; }
  }
}
const fmt = (h) => { const o = lch(h); return `${h}  L ${o.L.toFixed(3)} · C ${o.C.toFixed(3)} · H ${o.H.toFixed(0)}`; };
const nearest = (h) => Object.entries(HEADS).map(([n, v]) => [de(h, v), n]).sort((a, b) => a[0] - b[0])[0];
function check(h, tier, bg) {
  const o = lch(h), out = [], test = (ok, msg) => out.push([ok ? '  ok ' : ' FAIL', msg]), warn = (msg) => out.push([' 주의', msg]), a = anchor(o.H);
  if (tier === 'head') {
    test(Math.abs(o.L - a.L) <= 0.04, `밝기 L ${o.L.toFixed(3)} — 이 색상각의 기준 ${a.L.toFixed(3)} ± .04`);
    test(o.C - a.C <= 0.02, `채도 C ${o.C.toFixed(3)} — 기준 ${a.C.toFixed(3)} + .02 이하(넘으면 스티커가 아니라 형광)`);
    test(a.C - o.C <= 0.035 && o.C >= 0.025, `채도 C ${o.C.toFixed(3)} — 기준 ${a.C.toFixed(3)} - .035 이상, 그리고 .025 이상(모자라면 회색·먼지)`);
    test(cr(h, INK) >= 7, `잉크 글자 대비 ${cr(h, INK).toFixed(2)} — 7:1 이상`);
    const [d, n] = nearest(h);
    if (d < 0.0005) out.push(['  ok ', `기존 머리 색 ${n} 과 같은 값`]);
    else if (d < 0.02) warn(`가장 가까운 머리 ${n} 와 ΔE ${d.toFixed(3)} — .02 미만이면 같은 색으로 보인다(나란히 쓰지 말 것)`);
    else out.push(['  ok ', `가장 가까운 머리 ${n} 와 ΔE ${d.toFixed(3)}`]);
    for (const [lo, hi, m] of MEANING) if (lo < hi ? o.H >= lo && o.H <= hi : o.H >= lo || o.H <= hi) warn(`H ${o.H.toFixed(0)} 은 「${m}」 자리 — 그 뜻이 아니면 피한다`);
  } else if (tier === 'body') {
    test(o.L >= 0.965 && o.C <= 0.025, `L ${o.L.toFixed(3)}(.965 이상) · C ${o.C.toFixed(3)}(.025 이하)`);
    test(cr(h, INK) >= 9, `잉크 글자 대비 ${cr(h, INK).toFixed(2)} — 9:1 이상`);
  } else if (tier === 'chip') {
    test(o.L >= 0.9 && o.L <= 0.97 && o.C >= 0.018 && o.C <= 0.07, `L ${o.L.toFixed(3)}(.90~.97) · C ${o.C.toFixed(3)}(.018~.07)`);
    test(cr(h, INK) >= 7, `잉크 글자 대비 ${cr(h, INK).toFixed(2)} — 7:1 이상`);
  } else if (tier === 'strong') {
    test(o.L >= 0.81 && o.L <= 0.895 && o.C <= 0.105, `L ${o.L.toFixed(3)}(.81~.895) · C ${o.C.toFixed(3)}(.105 이하)`);
    test(cr(h, INK) >= 4.5, `잉크 글자 대비 ${cr(h, INK).toFixed(2)} — 4.5:1 이상`);
  } else if (tier === 'deep') {
    test(o.L >= 0.45 && o.L <= 0.58 && o.C <= 0.14, `L ${o.L.toFixed(3)}(.45~.58) · C ${o.C.toFixed(3)}(.14 이하)`);
    test(cr(h, PAPER) >= 4.5, `크림 종이 위 대비 ${cr(h, PAPER).toFixed(2)} — 4.5:1 이상`);
    if (bg) test(cr(h, bg) >= 4.5, `바탕 ${bg} 위 대비 ${cr(h, bg).toFixed(2)} — 4.5:1 이상`);
  } else throw new Error('층은 head | body | chip | strong | deep');
  const bad = out.some((x) => x[0] === ' FAIL');
  console.log(`${fmt(h)}  [${tier}]`);
  for (const [k, m] of out) console.log(`${k} ${m}`);
  console.log(bad ? '→ 탈락' : '→ 통과');
  return !bad;
}
function make(H) {
  const a = anchor(H), head = hex(a.L, a.C, H), body = mixWhite(head, 0.75), chip = mixWhite(head, 0.35), strong = hex(a.L - 0.055, Math.min(a.C * 1.45, 0.1), H);
  let deep = null;
  for (let L = 0.55; L >= 0.45 && !deep; L -= 0.005) { const d = hex(L, Math.min(0.1, maxC(L, H) * 0.8), H); // 경계까지 짜내면 쨍해진다
    if (cr(d, body) >= 4.5 && cr(d, PAPER) >= 4.5) deep = d; }
  for (const [n, v] of [['머리 head', head], ['몸통 body', body], ['칩 chip', chip], ['강조 strong', strong], ['진한 글자 deep', deep]]) console.log(n.padEnd(14), v ? fmt(v) : '없음');
  console.log('--- 검사');
  check(head, 'head'); check(body, 'body'); check(chip, 'chip'); check(strong, 'strong'); if (deep) check(deep, 'deep', body);
}
const [cmd, x, y, z] = process.argv.slice(2);
if (cmd === 'make') make(Number(x));
else if (cmd === 'check') process.exit(check(x.toUpperCase(), y, z && z.toUpperCase()) ? 0 : 1);
else console.log('사용: make <색상각> | check <#hex> <head|body|chip|strong|deep> [바탕 #hex]');
```
